## 文档
首先，如果你是linux党，那我得教你个函数
  - **`linuxTerminalCheck()`**  
      这个函数用于检测你是不是在tty环境内，无论你要搞阻塞输入还是无阻塞输入，你都有必要用这个函数检测一下环境
      当它返回`True`时，这代表你确实在tty环境里，但如果它返回`False`，那说明你可能不在纯tty环境内，这可能会导致阻塞错乱
  
然后就是接下来的函数了
  - **`getTerminalSize()`**  
    这个函数会返回一个元组，它的第一个元素是终端宽度（列数），第二个元素是终端高度（行数）
  - **`initGame()`**  
    它负责进入备用屏幕、隐藏光标，并初始化内部屏幕缓冲区。Windows 上还会自动开启 ANSI 转义支持，Linux/macOS 上会进入 cbreak 输入模式
  - **`clear()`**  
    清空内部屏幕缓冲区，并把所有行标记为需要重新绘制；下一次 `refresh()` 会擦掉上一帧的内容。常见写法是 `clear()` → 重新绘制 → `refresh()`
  - **`getch(nodelay=True)`**  
    最难实现的一个，因为它同时包含了Windows的输入，Linux的输入，且两个系统的输入都有分别的阻塞版和无阻塞版，通过`nodelay`这个参数来控制，默认是`True`
    如果你开了无阻塞输入，那么当你没有按任何按键时，他会返回`None`
    Linux/macOS 下只在纯 tty 内保证有效；输入会按 UTF-8 解码，因此中文等多字节字符不会被拆坏
  - **`drawChar(x, y, char, color)`**  
    它会在指定的`x`和`y`画一个你传入的字符。越界时会返回`False`并且不绘制，不会因为负坐标或超出屏幕而崩溃
    至于它的原理......好吧我可以讲讲
    其实我们还有一个内部变量`_screen`，这是一个数组，里面存的是各个位置对应的字符，当你调用这个函数时，它会把你传入的字符和你传入的坐标组合成一个元组丢进这个数组的对应位置里，但是屏幕左上角的坐标其实是(1,1)而不是(0,0)
    我们贴心的帮你把`x`和`y`调换了一下，这是因为实际绘制时是`y`在前`x`在后，但我们不想让你受苦，所以在这个函数里就把`x`和`y`调换了
    以及就是当你往color传入相应的参数时可以改变字符的颜色，颜色常量已经内置在了库里，比如`COLORRED`这样，该参数的默认值是`COLORDEFAULT`
  - **`drawStr(x, y, string, color)`**
    内部会逐次调用`drawChar`，`x`和`y`是字符串的起始坐标，从左往右打印，参数都和`drawChar`差不多
  - **`refresh()`**
    调用这个函数会重绘被修改过的行。每行只定位一次，颜色变化时才发送颜色代码，行尾用擦除序列清空，从而减少输出量
  - **`cursorEcho(echo=False)`**  
    当你往`echo`里传入`False`，这会隐藏你的光标
    如果传入`True`，光标又会显示出来
    以及`echo`的默认值为`False`
  - **`endGame()`**
    恢复光标、自动换行和备用屏幕，并恢复终端输入设置，但不会退出 Python。适合放在 `finally` 里
  - **`exitGame()`**  
    恢复终端并退出游戏；内部会调用 `endGame()`
  - **`frameStart()`**  
    如果你想控制帧率，可以试试这个，在每次主循环的开头调用它，切记一定要是最最最开头，前面不能有其他代码，然后配合`sleepForFrame()`使用，就可以控制帧率
  - **`sleepForFrame`**  
    它会根据 `frameStart()` 记录的本帧起点，补足到 `1 / fps` 秒，从而达到你传入的帧率
  - **`theLifeAndEverythingAndUniverseUltimateAnswer()`**
    我承认它的函数名真的很长，这是个彩蛋函数，无论你怎么调用它都会返回42

这基本就是全部内容了，祝你们能做出好的游戏！（虽然这个库基本没啥用）
